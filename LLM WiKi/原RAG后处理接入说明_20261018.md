# 原 RAG 时效、上下文与 Wiki 融合接入说明

当前为本地公开快照验证通过的可选择启用模块，尚未部署。它不替代向量召回，不修改 Milvus，也不提供任意私有知识访问。全国 RAG、身份认证和租户权限仍由已有主流程承担。

## 调用位置

主流程先完成可信身份与公开政策授权校验，再执行原 RAG，最后把成功响应中的文档 ID 交给后处理模块。`results` 或 `citations` 二选一，必须包含 `doc_id`。响应中的分数、正文和错误堆栈不会用于生成摘录；示例只有温江、蒲江已导出的公开快照，不会跨库回取缺失文档。

```python
from evidence_store import EvidenceStore
from rag_refinement import PublicRAGRefiner

refiner = PublicRAGRefiner(EvidenceStore())
review = refiner.refine_observation(
    question,
    county=trusted_county,       # 温江区 / 蒲江县；来自主流程
    as_of=explicit_query_date,   # YYYY-MM-DD
    rag_payload=public_response, # {'results': [{'doc_id': '...'}]}
    rag_state=actual_state,      # ok / empty / error / denied
    public_policy_access=trusted_public_policy_access,  # 必须是真正 bool
)
```

拒绝与故障不解析响应，也不调用 Wiki 兜底。`empty` 与非空候选冲突会报错。授权成功但召回为空时，允许使用已核对的公开 Wiki 线索。任何格式、来源或快照一致性异常应进入技术错误分支，不得改写成“当地无政策”。

## 返回值与生成边界

|字段或状态|调用方处理|
|---|---|
|`historical_evidence_for_review` / `documents`|历史证据审阅；保留每份文件的时效疑点和原始标记|
|`current_evidence_missing`|`documents` 为空；`review_candidates` 只供核查，不能拿来回答当前资格、补贴或申报|
|`needs_region_clarification`|按县区拆分或澄清，不能拿单县候选回答跨县问题|
|`access_denied`|沿用主流程拒绝|
|`rag_error_no_silent_fallback`|暴露原 RAG 技术故障，不能自动换成 Wiki 成功回答|
|`excluded`|保留未来发布、来源版本冲突、非本县等排除原因|
|`background_references_not_in_context`|被本地文件占用名额后留下的全国背景来源元数据，不是已提供的上下文原文|

`context_spans` 中每段文本都有实际 chunk_id 与字符偏移。每份本地文件最多 4,000 字、5 段；优先保留召回锚点，再按问题词语选择范围、排除项、限制、用途、原则或生效条款。没有跨块顺序推断或伪造块号。`context_truncated` 表示未回取该文档所有已导出文本，不能把少量片段当成完整政策。

原始有效/废止标记不会被改写。历史模式保留旧文件供查阅；当前模式即使原库标记有效，也须核对官方现行版本。正文日期与存储字段冲突在 `temporal` 内显示。只有元数据而没有完整档案的文件明确标为 metadata_only，不把发布日期当生效日。

融合保留原召回首个本地候选，再补充本地 Wiki 命中文件，保留其他未知候选。全国历史背景在有本地 Wiki 命中时仅填充剩余名额；只有全国主题线索时，在首个本地候选后纳入背景。未加入 Wiki 的 2024 年文件不会因年份较新或未整理就被判错，2021 年 Wiki 文件也不自动被视为现行。

## 当前验证与上线所需

已通过 82 项检查，及同一批 20 道开发题复测。原始问句、标签、时间和公开快照不变；详见 `offline_comparison_20261018_v7/优化复测报告.md`。这不是线上向量复现或独立准确率评测。

上线前需由实际服务负责人确认正在运行的版本、调用位置及完整授权过滤；之后将本模块部署为可关闭的后处理分支，用原请求参数和真实日志回放。当前原型只用已导出的 9,463 个公开片段，不能直接当成覆盖全国的在线回取器；正式回取实现必须继续携带相同 tenant/visibility/auth_purpose、地区、doc_id 和来源约束，不能仅按 doc_id 跨权限查询。这里没有执行生产热替换。

政策采集成员的两份原件核查、实际调用日志仍按此前已发材料跟进。无需重新发一轮清单。原件返回后再复核知识与时效，再生成新快照及新进程实例。
