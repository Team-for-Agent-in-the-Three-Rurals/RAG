# Wiki 独立证据节点：离线接入与状态约定

本轮实现：`wiki_node_adapter.py`。当前输出模式为off/offline/shadow，均不调用模型或检索服务，不连接数据库；on模式会被拒绝。构造参数控制模式，程序没有自动读取SANONG_WIKI_MODE环境变量。主流程和线上服务未修改。

## 服务端调用

```python
import asyncio
import json
from wiki_node_adapter import OfflineWikiNode, TrustedPublicAccess

# manifest是受控发布文件；expected来自服务端固定版本配置，不能从请求JSON取得。
manifest = json.load(open("offline_node_integration_20261019_v2/wiki_release.json"))
node = OfflineWikiNode(
    manifest=manifest,
    expected_version=EXPECTED_WIKI_VERSION_FROM_SERVER_RELEASE,
    mode="shadow",
)

result = await asyncio.to_thread(
    node.update_state,
    state,
    question=question,
    requested_region={"province":"四川省", "city":"成都市",
                      "county":"温江区", "region_code":"510115"},
    as_of="2026-10-18",
    top_k=5,
    wiki_version=EXPECTED_WIKI_VERSION_FROM_SERVER_RELEASE,
    auth_context=TrustedPublicAccess(allowed=server_allows_public_policy),
    rag_payload={"citations":state.get("rag_results", [])},
    rag_state=actual_rag_state,  # ok / empty / error / denied
)
for key in ("rag_evidence", "wiki_evidence", "evidence_conflicts", "wiki_review_candidates", "wiki_node"):
    state[key] = result[key]
```

函数同步，现有异步编排可用asyncio.to_thread。`update_state`返回副本；上例只合并新增字段，不重新赋值覆盖原RAG结果。推荐挂在政策证据取回后、smart_pipeline的证据审阅/生成前。现有政策节点的草稿骨架可以保留为基线，不能直接当最终核验结论。

授权对象必须由服务端可信逻辑构造，客户端dict会被拒绝。其权限只对应这批公开Wiki快照，不会证明原RAG已执行文档级权限过滤。原RAG公开范围约束仍须在召回前完成；不得把此节点的公开授权对象当作修复整个权限链路。拒绝时不访问Wiki源文件、不解析错误正文。off模式不要求补齐Wiki专用日期/地区等参数，也不调用Wiki。

## 字段映射与三条来源链

|原字段|规范字段|行为|
|---|---|---|
|policy_code|doc_id|保留原字段名记录；双字段值冲突报RAG_ALIAS_CONFLICT|
|unit_code|chunk_id|原样定位，不编造ID|
|url|source_url|未知留null|
|date|publish_date|不替代生效日期|
|score|score_metadata.returned_score|保留为原始排序元数据，不解释为概率|
|context_chunks|独立rag_reference_id及context_index|与父文件冲突报错；各片段可分别追溯|

`rag_evidence`是规范化视图，原`rag_results`、`citations`、`draft_answer`、`answer`及`analysis`等字段不改。未知额外字段不回显进新契约，原state中原始引用仍在。RAG错误正文不解析、不回显。

每条Wiki证据都有evidence_id、statement_id、wiki_version、statement、quote及定位。

- wiki_chain：Wiki标识、内容版本、结论ID、层级。
- rag_chain：关联到实际RAG返回的引用ID和doc/chunk。明确区分quote_in_returned_rag与same_document_only_not_quote_support；同文档不等于该片段支持当前引文。没有RAG对应时为空。
- primary_source_chain：原文快照路径/hash、具体记录/字符位置及原文摘录；全国文件另保留适用范围证明的源文件链。例如2021复函的条款和2019试点名单分别保留。

兼容成员一建议的source_chains.wiki/rag/primary三字段，同时给出上述显式名称。全国Wiki独有材料的doc_id/chunk_id为null，不伪造Milvus映射。

`verify_primary_links()`重新打开发布清单登记过的本地快照，检查文件/记录hash和连续摘录偏移；拒绝清单外路径、篡改摘录或版本变更。不抓URL，不访问任意文件。quote_verified仅表示去除排版空白后的原文连续匹配，statement_supported仍为null；这不是语义蕴含、官方当前效力或项目资格验收。

日期分开保存：publish_date为已有发布日期；effective_from/effective_to只取正文中可明确解析的绝对日期；abolished_at未知为null。原库valid_from/valid_to保留在metadata_values，正文冲突列入evidence_conflicts；不把两年/三年有效期硬算成官方到期日。地区区分source_region与requested_region；试点名单证明的范围只用于历史审阅，不推广为当前资格。

## 状态联调

|节点status|含义/动作|
|---|---|
|disabled|不使用Wiki结果，继续原流程|
|access_denied|遵守拒绝；不查Wiki|
|needs_region_clarification|地区层级/代码或跨县问题冲突，先澄清|
|partial_failure|保留各路状态和错误；另一条来源正常不能掩盖故障|
|needs_current_evidence|当前证据不足；wiki_evidence为空，历史材料只在review_candidates|
|source_missing|已定位缺正文，转补原文；关联文件也仅放review_candidates，不替代缺失文件|
|wiki_only_review|RAG为空但Wiki有历史证据，只供审阅|
|historical_review_only|已有历史证据可核查，不证明当前适用|
|evidence_gap|两路材料不足或Wiki未覆盖，不表示当地无政策|
|continue_original_rag|Wiki未提供证据，原流程按自身状态继续|

rag_state、wiki_status、errors分开保留。节点status仅描述证据分支，不能覆盖主流程analysis.status或HTTP错误。本轮始终answer_generation_authorized=false、can_support_current_application=false，没有把离线契约自动接入生成模型。
