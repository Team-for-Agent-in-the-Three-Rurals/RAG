# 第四步：RAG＋Wiki接入智能体政策问答（2026-10-19）

已完成本地问答路径与主流程接线候选。与此前只输出证据包的节点不同，本轮实际执行接线后的政策问答、原质检和最终响应，产出有逐条来源的用户答复。
本轮采用原文摘录式答复，不调用付费LLM；未部署远端应用。

## 已接入

- 第三步增量守卫：读取前、答复前和最终响应处检查版本，过期时不沿用旧摘要。
- RAG旧字段别名、真实doc/chunk、原文位置与Wiki版本链；同文档命中不冒充引文支持。
- 专题、具体对象、所问字段、指定文件年份和地区一致性检查；避免把住户调查或其他文件年份混入答复。
- 对象、条件、限制和时间的可见原文上下文；原定期限与当前效力分开。
- 当前申报/资格/额度证据不足时，不输出旧金额或确定资格；历史材料只保留审阅入口。
- 未找到、缺正文、技术故障、权限拒绝、版本过期和引用核验失败分别处理，均不推断政策不存在。
- 最终输出核验：后续节点写入旧答复、无依据金额或伪造引用时，不直接透传给用户。

## 验证结果

**全套200项测试通过**，其中38项为本轮问答回归。[原始日志](test_run_final.txt)。

33个问题执行了捕获源码中的`_run_agent`、已接线的政策节点、原有`grade_result`、审核提示及最终响应。题目包括20道既有开发题、3份老师历史响应和10个补充场景；参考时点统一到当前构建2026-10-19，原时点保留在冻结题单中。

| 状态 | 回放数量 |
|---|---:|
| 有引用的历史文本答复 | 21 |
| 当前证据待补 | 5 |
| 本次证据不足 | 2 |
| 地区待澄清 | 1 |
| 所问正文缺失 | 1 |
| 明确RAG故障并单独保留Wiki历史引文 | 2 |

实际进行26次本地公开片段BM25检索；保存的历史响应和合成故障与新检索分开标记。没有线上Milvus/HTTP调用，没有外部付费LLM调用。
上述是功能、引用与状态验证，不是独立答案准确率，也不是第五步原RAG/优化RAG/优化RAG＋Wiki的正式三组评测。
